1. Ограничения среды (Project Zomboid / Kahlua)
Язык: Kahlua (интерпретатор Lua 5.1 на базе Java). Стандартные библиотеки io.*, os.*, debug.* недоступны.
Файловый ввод-вывод: Используй только глобальные функции PZ API: getFileReader, getFileWriter (для работы с кэшем и конфигами в папке Zomboid/Lua/) и getModFileReader (для чтения файлов модов). ZomboidFileSystem из Lua недоступен — не используй его.
Многопоточность и фон: В главном меню игры (где находится селектор модов) Events.OnTick НЕ работает. Для фонового выполнения Lua-корутин (coroutine) используй Events.OnFETick (Front-End Tick) или привязывайся к методу update()/prerender() UI-панели.
Загруженные файлы: Для получения списка Lua-файлов используй getLoadedLuaCount() и getLoadedLua(index).

3. Архитектура Слоев (Layers) и Категоризация
Мод строится на расширяемой архитектуре слоев. Это нужно для легкого добавления новых слоев в будущем (например, интеграция со сторонними модами-менеджерами).

Каждый слой должен регистрироваться в Core.lua и иметь единый интерфейс (например: init(), analyzeCoroutine(modsList), getModData(modId), getCategory(modId)).
Категории модов (строгий порядок приоритета загрузки сверху вниз):
{ "coreRequirement", "tweaks", "resource", "map", "vehicle", "code", "weapon", "clothes", "items", "ui", "other", "translation", "undefined" }
Каждый слой может предложить категорию для мода. Приоритет определения категории: Слой 3 (Кастомные правила) -> Слой 2 (Теги и mod.info) -> Слой 1 (По анализируемым файлам: например, наличие папок media/maps, скриптов транспорта, переводов и т.д.).
4. Детальные требования к модулям
4.1. Core/utils.lua
Функции для работы с таблицами: глубокое копирование, merge, isEmpty, indexOf, keys.
Строковые утилиты: trim, split, очистка от комментариев Lua.
Сериализация и десериализация Lua-таблиц (в текстовый формат или JSON-подобный вид) для сохранения кэша и правил через getFileWriter / getFileReader.
4.2. Core/Core.lua
Глобальная таблица мода, хранящая состояние анализа, кэш и зарегистрированные слои.
Менеджер корутин: Функция запуска анализа всех слоев в фоне (через coroutine.create и coroutine.resume в Events.OnFETick), чтобы интерфейс игры не зависал. Должен отдавать прогресс (в процентах или статусах) для отображения в UI.
4.3. Layers/1_ModsFiles.lua
Анализирует файлы модов. Ищет перезаписи глобальных объектов и их методов (например, function ISInventoryPane:prerender()).
Резолв алиасов: Парсер должен понимать локальные алиасы. Если в файле написано local InvPane = ISInventoryPane, а ниже function InvPane:prerender(), слой должен записать, что мод перезаписывает ISInventoryPane:prerender. Игнорируй закомментированный код (-- и --[[ ]]).
Кэширование и инвалидация через Steam API:
Анализ файлов долгий, поэтому результаты (какие файлы и методы меняет мод + вычисленная категория) должны сохраняться в файл кэша.

4.6. Core/SortingCore.lua (Алгоритм сортировки)
Сортировка вызывается по кнопке в UI (когда фоновый анализ завершен) и работает строго по следующим шагам:

Определение категорий: Для каждого активного мода запрашивается категория у слоев (приоритет: Слой 3 -> Слой 2 -> Слой 1 -> иначе "undefined").
Построение графа зависимостей: Собираются все связи "Мод А должен быть загружен ДО Мода Б" из:
Слой 3 (Кастомные правила) — высший вес.
Слой 2 (require, loadAfter, loadBefore).
Слой 1 (Конфликты перезаписи функций: если два мода меняют одну функцию, и нет явных правил, используй эвристику, например: мод с меньшим общим числом изменений грузится позже как патч).
Динамическое повышение категорий (Category Promotion) — КРИТИЧЕСКИ ВАЖНО:
Если Мод А зависит от Мода Б (т.е. Мод Б должен грузиться раньше Мода А), то категория Мода Б должна быть не ниже (по приоритету загрузки) категории Мода А.
Пример:
Список категорий: 1: coreRequirement ... 5: vehicle, 6: code ... 12: translation.
Если Мод_Машина (категория vehicle, индекс 5) требует Мод_Код (категория code, индекс 6), то Мод_Код должен принудительно изменить свою категорию на vehicle (индекс 5), чтобы загрузиться раньше Мод_Машина и не сломать общий порядок категорий!
Реализуй обход графа зависимостей для рекурсивного "подтягивания" категорий всех зависимостей вверх.
Предварительная сортировка: Сортировка модов по их итоговым категориям (от coreRequirement к undefined), а внутри одной категории — по алфавиту (по Mod ID или имени).
Топологическая сортировка: Применение зависимостей с сохранением порядка категорий и алфавитного порядка там, где нет жестких связей. Обязательно реализуй защиту от циклических зависимостей (Circular Dependency Detection): при обнаружении цикла логируй предупреждение, разрывай наименее приоритетную связь и продолжай сортировку, чтобы игра не зависла.
4.7. ModSelector/ModSelector_overrides.lua
Перехват открытия окна настройки порядка модов (ModLoadOrderPanel или соответствующий экран в ModSelector).
При открытии этого окна автоматически запускается фоновый анализ модов (через Core.lua).
На экран добавляется индикатор прогресса анализа (например, "Analyzing mods: 45%...") и кнопка "Auto-Sort" (неактивна, пока идет анализ).
При нажатии на "Auto-Sort" вызывается SortingCore, полученный список применяется к текущему списку активных модов, и UI-список обновляется.
