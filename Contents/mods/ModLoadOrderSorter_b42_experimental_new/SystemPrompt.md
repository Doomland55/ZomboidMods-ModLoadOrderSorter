## 1. Ограничения среды (Project Zomboid / Kahlua)
1. **Язык:** Kahlua (интерпретатор Lua 5.1 на базе Java). Стандартные библиотеки `io.*`, `os.*`, `debug.*` недоступны.
2. **Файловый ввод-вывод:** Используй только глобальные функции PZ API: `getFileReader`, `getFileWriter` (для работы с кэшем и конфигами в папке `Zomboid/Lua/`) и `getModFileReader` (для чтения файлов модов). `ZomboidFileSystem` из Lua недоступен — не используй его.
3. **Многопоточность и фон:** В главном меню игры `Events.OnTick` НЕ работает. Для фонового выполнения Lua-корутин (`coroutine`) используй `Events.OnFETick` (Front-End Tick) или метод `update()`/`prerender()` активной UI-панели.
4. **Загруженные файлы:** Для получения списка Lua-файлов используй `getLoadedLuaCount()` и `getLoadedLua(index)`.

4.5. Layers/3_SortingRules.lua
Управляет кастомными правилами для каждого modId:
Списочные правила: loadAfter (table), loadBefore (table), incompatibleMods (table).
Категория: category (string).
Позиционные правила loadFirst и loadLast, каждое из которых имеет 3 состояния:
"off" — настройка игнорируется (по умолчанию).
"on" — загружать в самом начале (loadFirst) или самом конце (loadLast) всего глобального списка модов.
"category" — загружать в самом начале (loadFirst) или самом конце (loadLast) внутри своей текущей категории.
(Примечание: loadFirst и loadLast взаимоисключающие — если одно ставится в "on" или "category", второе автоматически сбрасывается в "off").
Поддерживает два состояния в памяти: Saved Rules (состояние из файла) и Working Rules (рабочая копия в памяти для редактирования и Симуляции, с возможностью полного отката к Saved Rules).
4.6. Core/SortingCore.lua (Алгоритм сортировки)
Принимает список модов и набор правил (Saved или Working для симуляции).

Категоризация: Назначает категории модам со всех слоев. Моды с loadFirst = "on" и loadLast = "on" выделяются в специальные приоритетные группы в самом верху и самом низу глобального списка.
Динамическое повышение категорий (Category Promotion) — ВАЖНО:
Если Мод А зависит от Мода Б (Б должен грузиться раньше А), то категория Мода Б обязана быть не ниже (по приоритету загрузки) категории Мода А.
Пример: Порядок категорий: ... vehicle (5), code (6) .... Если Мод2 (vehicle) требует Мод3 (code), то Мод3 обязан динамически сменить свою категорию на vehicle, чтобы загрузиться до Мод2 без нарушения глобального порядка категорий! Реализуй рекурсивный обход графа зависимостей для подтягивания категорий вверх.
Предварительная сортировка: Сортировка по итоговым категориям (учитывая loadFirst = "category" и loadLast = "category", которые ставятся в начало/конец своей категории), а внутри одной категории — по алфавиту.
Топологическая сортировка: Применяет граф правил (require, loadAfter, loadBefore и эвристику перезаписей из Слоя 1), сохраняя порядок категорий. При обнаружении циклических зависимостей (Circular Dependency) или активных несовместимых модов — разрывать наименее приоритетную связь и вызывать WarningPopup.lua с подробным описанием проблемы для пользователя.

Ниже под кнопками — 3 выпадающих списка (ISComboBox) для выбранного мода:

Load First (значения: off, on, category).
Load Last (значения: off, on, category).
Правая часть (3 скролл-листа друг под другом):

Верхний список: Отображает моды, которые входят в выбранный в данный момент режим редактирования (loadAfter, loadBefore или incompatibleMods).
Средний список (Required): Моды, которые требует выбранный мод.
Нижний список (Required By): Моды, которые требуют выбранный мод.
Логика работы и Toggle-режим редактирования:

Обычный режим (режим редактирования не выбран): Клик по моду в левом списке делает его активным, активирует центральную панель, обновляет выпадающие списки (Category, Load First, Load Last) и заполняет правые списки Required и Required By.
Toggle-режим редактирования (нажата кнопка loadAfter, loadBefore или incompatibleMods):
Списки Required и Required By справа не меняются.
Верхний правый список заполняется модами из соответствующего правила выбранного мода.
В левом списке сам редактируемый мод становится серым (замораживается), а все моды, входящие в редактируемое правило, подсвечиваются отдельным цветом (отличным от выделения и ошибок).
Пока режим активен, клики по другим модам в левом списке добавляют или удаляют их из временного списка этого правила (мгновенно обновляя верхний правый список и подсветку в левом списке).
Нажатие кнопки "Применить" фиксирует эти изменения в Working Rules (в памяти) и выходит из режима редактирования. Повторное нажатие на кнопку самого режима (или кнопку "Отменить") сбрасывает несохраненные клики этого режима и выходит из него.
Быстрая навигация: При клике на любой мод в любом из трех списков справа (если не активен Toggle-режим, либо с автоматическим выходом из него) — этот мод автоматически выбирается в левом списке для быстрого перехода к его редактированию. При необходимости используй ContextMenu.lua для дополнительных быстрых действий по ПКМ.
Нижняя панель управления окном Редактора:

"Выход без сохранения": Полностью откатывает Working Rules к состоянию из файла на диске и закрывает редактор.
"Симуляция": Запускает SortingCore для левого списка модов в редакторе, применяя текущие Working Rules (включая все "Примененные" изменения, но БЕЗ сохранения их в файл на диске), перестраивает левый список и обновляет цветовую валидацию ошибок.
"Сохранить и выйти": Записывает Working Rules в файл на диске через Слой 3, обновляет ModLoadOrderPanel и закрывает редактор.
